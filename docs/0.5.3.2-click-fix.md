# 0.5.3.2: correct the tile button validation layer

The 0.5.3.1 safety change incorrectly required the outer hand-tile component to
be an enabled `Button`. The existing reader and UI dumper describe a different
hierarchy: hand tile container -> NodeList[0] button component -> image.
The strict type/enabled checks belong to that inner button, not the container.

The local Dalamud log on 2026-11-24 records this symptom twice:
07:40:14 and 07:40:31 JST, slot11 highlight at state6, observed transition to
state30, then `click: slot 11 has no button node` and fail-closed shutdown.
There is no `click: begin` in either attempt, so these failures precede native
click dispatch. They are distinct from the earlier 07:03 access violation.

The resolver now follows the configured child index and checks that actual
child's visibility, component type, owner and enabled status. Addon-owned
ButtonClick validation, single-send handshake, and the ban on raw callback
fallback remain in place. Failure messages now distinguish missing/hidden nodes,
wrong child component type, disabled buttons, missing click events and changed
states rather than collapsing them all into "no button node".

Eight regression cases exercise the production resolver with a non-button
container and nested button, hidden/missing components, a disabled child,
wrong component type and missing owner. They do not reproduce native game
dispatch; real-match confirmation after updating remains necessary.
