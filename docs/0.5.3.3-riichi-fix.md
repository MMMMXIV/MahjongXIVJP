# 0.5.3.3: preserve the riichi declaration discard

The local Dalamud log at 2026-11-24 15:19:57 JST records a riichi declaration
choosing 8m. The next action instead highlights slot13 icon76044 (4m), followed
by state30 and `child button 9 is disabled`. No native click is dispatched.
Later ordinary discards in the same log successfully click slots12, 6 and 2.
This is distinct from the parent-container validation defect fixed in 0.5.3.2.

AutoPlayController checked `board.OwnRiichi` before its pending declaration tile.
The badge can appear while choosing the declaration discard, causing the driver
to choose the drawn tile instead of the tile used to decide riichi. The fix gives
the pending declaration precedence. Only later riichi turns choose slot13.
An invalid pending target fails closed instead of falling through to tsumogiri.

Six regression cases cover the badge both on and off during declaration, later
riichi turns, normal turns and missing/out-of-range declaration targets. The
production routing function is linked into the tests. Disabled-button checks,
single-send handshake and the prohibition on raw callback fallback are unchanged.

The log establishes the target mismatch and the source explains it. Live-match
verification that the intended declaration discard succeeds after updating is
still required; the tests do not execute the game's native UI.
