# 麻雀AIエンジン 設計と検証

このドキュメントは、MahjongXIV JP の思考エンジン（`MahjongXiv.Engine`）と、その評価に使うオフラインシミュレーター（`tools/MahjongXiv.Simulator`）の設計をまとめたものです。数値は README の「検証結果」節を参照してください。

## 全体構成

```
TurnInput ─┬─ DiscardEvaluator.Rank   既存の価値ランキング（牌効率・形の先読み・1シャンテンEV）
           │
           └─ TurnPolicy.Decide
                 ├─ Options.AnyStrategic = false → 既存ロジック（TurnPolicy.Legacy）
                 └─ Options.AnyStrategic = true  → StrategicPolicy（戦略層）
                        ├─ DefenseModel      放銃確率（相手ごと・牌ごと）
                        ├─ WinModel          残り巡目での和了確率／放銃確率（巡目ごとの遷移）
                        ├─ PlacementModel    着順期待値（得点 → 効用）
                        └─ TenpaiInfo        待ち枚数とリーチ／ダマ・ロン／ツモ別の打点
CallInput ─── CallPolicy.ShouldPon(input, options)  SmartPon: 鳴かない場合と鳴いた場合の期待値比較
ScoreCalculator / FuCalculator                      符・翻・支払い（本場・供託）
```

既存の `DiscardEvaluator` は書き換えず、その順位付けを「攻撃側の候補」として使い、戦略層が局面に応じて最終判断します。新機能はすべて `EvalOptions` の機能フラグで個別にオン・オフでき、`EvalOptions.Default` は従来とまったく同じ判断をします（シミュレーターで差が 0 になることを確認済み）。

| フラグ | 内容 |
|---|---|
| `PushFold` | 押し引き。候補打牌ごとに「押した場合の期待値」と「オリた場合の期待値」を比較 |
| `RiichiJudgement` | リーチ／ダマを期待値で選択（従来はテンパイ即リーチ） |
| `PlacementAware` | 得点ではなく着順期待値で結果を評価 |
| `SmartPon` | ポンを期待値で判断（従来はルールベース） |
| `EvalOptions.Strategic` | 上記すべてオン。プラグインの「戦略AI」設定で使用 |

## Phase 1: 点数計算

- `FuCalculator`: 副底20符、門前ロン+10、ツモ+2（平和ツモを除く）、刻子・槓子（幺九・暗刻で倍）、役牌雀頭（連風牌は4符）、嵌張・辺張・単騎+2、切り上げ、喰い平和形30符、七対子25符。
- `ScoreCalculator`: 基本点 = 符 × 2^(翻+2)、満貫（2000）・跳満・倍満・三倍満・役満。親6倍／子4倍、ツモの親・子払い、本場（300点）・供託。
- `YakuCalculator.Interpretations` が手牌の全解釈（面子分解 × 和了牌の位置、七対子、国士）を返し、`ScoreCalculator` は**点数が最大の解釈**を採用します（翻数最大と一致しない場合があるため）。
- **ドマ式麻雀の点数表は未確定です。** 既存コードは「符なし・翻数のみ」（`ScoringRules.DomanFlat`）を前提にしていましたが、実際のゲーム結果画面での確認はされていません。標準の符計算（`ScoringRules.Standard`）も実装し、どちらでも評価できるようにしています。切り上げ満貫・ダブル役満も設定で切り替え可能です（既定はオフ）。

## Phase 3: 守備（DefenseModel）

テンパイしている相手に対する放銃確率を、待ちの形ごとの寄与の合計で推定します。

| 待ち | 重み | 無効になる条件 |
|---|---|---|
| 両面（片側ごと） | 4.5% | 相手の河にスジ牌（t±3）がある |
| 嵌張 | 2.0% | 両隣の牌が見えている枚数に応じて減衰 |
| 辺張（3・7） | 1.5% | 同上 |
| シャンポン（数牌／字牌） | 1.2% / 3.5% | 残り枚数が2枚未満 |
| 単騎（数牌／字牌） | 0.5% / 1.5% | 残り枚数が0 |

構成牌の残り枚数で可用性を掛けるため、壁（ノーチャンス・ワンチャンス）が自然に反映されます。全形が生きている場合、合計は一般に知られる値（無スジ4〜6：約12〜13%、3・7：約10%、2・8：約8%、1・9：約6%、両スジ：約4%、生牌字牌：約5%）になるよう調整しています。

- 現物、およびリーチ宣言後に他家が切って通った牌は安全牌（0）として扱います。
- リーチしていない相手は、副露2つ以上でテンパイ確率（巡目で増加）を付与します。門前のダマテンは観測できないため想定しません。
- 損失額は相手の親子・リーチ有無と点数表から決め、着順評価がオンなら効用に換算します。

## Phase 3/4: 押し引きとリーチ判断（WinModel / StrategicPolicy）

`WinModel.Run` は残りツモ回数にわたり、「前進（有効牌/未知牌）」「和了（自摸＋3人分の打牌×出やすさ）」「他家の和了で局終了」「自分の打牌による放銃」を巡ごとに遷移させ、和了確率・放銃確率・流局時テンパイ確率を返します。

候補打牌（価値ランキング上位5＋安全度上位4）ごとに

```
押し = P(和了) × 効用(打点 + 供託・本場) − P(以後の放銃) × 損失 − 今回の放銃確率 × 損失
オリ = −今回の放銃確率 × 損失 − 残り巡目のオリ失敗リスク
```

を計算し、最大のものを選びます。テンパイ候補ではリーチとダマを比較します。

- リーチ: 打点にリーチ1翻と裏ドラ期待値を加えます。相手の出やすさは下がりますが、他家の和了も減ります。オリられないため放銃ハザードは下がらず、不和了時は供託1000点を失います。
- ダマ: 役がなければロン不可（ツモのみ）で、後から降りられるため放銃ハザードは低めです。
- フリテン（自分の河・今回の打牌）はロン不可として扱います。

## Phase 5: 鳴き（SmartPon）

「鳴かずに門前を保つ価値（リーチ可能性込み）」と「ポン＋最善の打牌後の価値 − その打牌の危険度」を `PositionValue` で比較し、1.1倍＋α上回る場合のみポンします。テンパイ価値は役の成立を前提に計算するため、役なしになる鳴きは価値0になります。2シャンテン以上離れる場合は、従来の役ルール（役牌・役牌刻子・ドラタンヤオ）も満たす必要があります。チー・カンはゲームUIの操作が未検証のため対象外です（シミュレーターも同様）。

## Phase 6: 着順期待値（PlacementModel）

```
効用 = 0.25 × 自分の点数 + Σ P(順位 r) × 順位点[r]      順位点 = +30000 / +10000 / −10000 / −30000
```

- 各相手について「最終的に自分より上になる確率」を、点差を残り局数に応じた正規分布（1局あたり σ≈5500、残り0局でほぼ確定）でぼかして求めます。そこから順位分布（ポアソン二項分布）を計算します。
- 順位点は順位に線形なので、これを最大化することは平均順位の最小化と同じです。
- 和了・放銃・供託の各結果をこの効用の差に変換して押し引き・リーチ判断に使います。たとえばオーラスで逆転条件を満たす打点の価値が上がり、トップ目の無理な押しは価値が下がります。
- 固定の「オーラスならこうする」というルールは持ちません。

## シミュレーター

```bash
dotnet run --project tools/MahjongXiv.Simulator -c Release -- ab 1000 101 strategic=on
```

```bash
dotnet run --project tools/MahjongXiv.Simulator -c Release -- ab 1000 101 strategic=on rounds=1
```

```bash
dotnet run --project tools/MahjongXiv.Simulator -c Release -- ab 400 7 pushfold=on scoring=standard
```

```bash
dotnet run --project tools/MahjongXiv.Simulator -c Release -- examples
```

- `ab`: 対局 i ごとに同じ牌山で5回対局します。内訳は、候補AIが席0〜3に1人ずつ入る4回（相手は常に既存AI3人）と、既存AI4人の対照1回です。席と牌山の運は対局ごとのペアで相殺され、相手のバージョン差による交絡もありません。
- 出力: 平均順位、トップ率、ラス率、順位点、卓平均との得点差（95%信頼区間）、和了率、放銃率、リーチ率、平均和了点・放銃点、判断時間。
- 卓設定: `rounds=1|2`（東風／半荘）、`scoring=flat|standard`、`kiriage=on`。
- 候補設定: `strategic=on`、`pushfold=on`、`riichijudge=on`、`placement=on`、`smartpon=on`、`dealin=1.2`、`riichiron=0.55`、`damaron=0.7`、従来の `shape`/`tenpai`/`legacy`。
- `examples`: 代表的な牌姿で旧AIと新AIの判断を並べて表示します。

**シミュレーターの制限:**
- チー・カン・途中流局・アガリ止め・西入・トビ以外の終了条件は未実装です。
- オーラス親の連荘は上限付きで継続します。
- 局終了時に卓に残った供託はトップが取ります。
- 赤ドラは各色1枚です。
- 点数表は既定で DomanFlat です。

## 性能

- 打牌判断はシミュレーター単スレッドで平均約2〜3ms、最大でも数十msです（主に2シャンテン以上での形の先読み）。
- 有効牌探索で、改善し得ない牌（手牌に同種も2以内の隣接牌もなく、国士にも関係しない牌）を厳密に除外し、評価回数を削減しました。
- 1シャンテン先読みのテンパイ評価を判断内でメモ化しています。
- プラグインでは打牌判断を `DecisionWorker`（バックグラウンドスレッド）で計算します。UI描画やフレーム更新を止めません。
